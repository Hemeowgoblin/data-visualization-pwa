- there will be a "snap" button, when clicked it will download a compressed folder that has a PNG and an SVG of the pie chart, the bubble chart, the horizontal bar chart, and the line plot with the vertical scrubbing line.
- the website will have the Responsive Dual-View: On desktop, place the Pie Chart and Line Plot side-by-side with a shared horizontal slider underneath. On mobile PWAs, use a "Switch View" toggle so the user can choose which chart to watch while sliding.
- To stay within hosting limits while offering PNG/SVG "snaps," perform all image rendering client-side in the user's browser (using libraries like Canvas or FileSaver.js) so your server does zero work.
- Updating multiple SVG components (Pie and Line) in real-time as a user drags a slider can cause the browser's "Main Thread" to lock up. This results in "janky" animation that feels amateur rather than professional. Use Web Workers to handle the data filtering of the JSON/CSV files in the background. As the user moves the slider, the Worker calculates the values and sends only the "diff" to the charts.
- Generating a "Snap" that combines two separate charts into one high-quality PNG/SVG client-side is computationally expensive for mobile devices (PWA focus). Render the "Live" preview on a HTML5 Canvas (extremely fast for sliders) but generate the "Snap" export using a hidden SVG element. This gives the user a smooth 60fps experience while still providing the high-quality vector export they need for presentations. 
- Standardized "Snapshot" Templates: Instead of just a "Pie," create a library of "Snapshot Components" (Pie, Bar, Bubble) that all share the same data interface. This allows you to "vibe code" the logic once and swap the visualization based on the specific FRED metric we choose later.
